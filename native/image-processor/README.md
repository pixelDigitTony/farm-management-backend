# Farm image processor

Rust owns candidate search, bounded buffers, quality checks and file output. The narrow C++ bridge owns libvips image handles and native buffer allocation. Every exception is caught at that boundary; Rust frees each handle/buffer once. The binary has no database or network dependencies.

Linux Docker is the supported runtime. Build the `processor` stage in `deploy/Dockerfile.images`; the committed Cargo.lock is required for locked release builds. Run `cargo test`, `cargo fmt --check` and `cargo clippy -- -D warnings` in the build stage. Native development requires Rust 1.90.0, a C++17 compiler, pkg-config and libvips development headers. Set `FARM_VIPS_BUNDLE_ROOT` to the backend's `node_modules/@img` directory to link the exact Sharp native bundle pinned by package-lock. Docker does this automatically. The adapter uses the stable libvips C/C++ API and links its GLib symbols from the same monolithic bundle; it never mixes system and bundled codec libraries.

The production default remains Sharp. Rust requires `IMAGE_PROCESSOR=rust` and an absolute `IMAGE_RUST_BIN`; startup runs a codec/metric self-test. The binary uses the same pinned SSIMULACRA2 CLI, never a replacement score. Each attempt is a fresh process capped at 1536 MiB address space on Linux, with a parent deadline and process-tree termination. This cap is an initial safety setting; representative near-limit workload testing remains required before adoption.

The standalone native pipeline is experimental until the complete corpus, benchmark and deployment gates in the spec pass. The small normalization audit now matches Sharp pixels exactly across orientation, P3, CMYK, grayscale, 16-bit, alpha resize and tiny PNG fixtures. Linking to older distribution codecs produced measurable differences; that diagnostic mode is not the packaged runtime. Startup tests an 8-pixel fixture and rejects native stacks unable to round-trip it. Native bundle versions and executable/metric hashes form the processing fingerprint.
